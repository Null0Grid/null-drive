# client/: Null Drive desktop app (Wails v2)

Keeps a local folder in sync with a Null Drive server, with a tray icon. Released for Windows and Linux; also builds on macOS.

| Path | What |
|---|---|
| `main.go` | Wails entry: window, single-instance lock, hide-to-tray; flags `--hidden` (autostart), `--quit` and `--forget` (installer), `--url <link>` (nulldrive:// links) |
| `ipc_windows.go` | Hands arguments (`--quit`, a link) to a running copy without starting Wails, through Wails' single-instance window |
| `link.go`, `openlink.go` | `nulldrive://open?id=` links: strict parsing, resolving the id with the server, opening the file from the sync folder (programs are revealed, never run), fallback to the web app |
| `shell_windows.go` | ShellExecute / reveal-in-Explorer, Windows' dangerous-type list, MSIX package detection, self-registering the scheme for the portable copy |
| `e2ee.go` | End-to-end encryption: unlock, key in the keychain, encrypted sync engine |
| `app.go` | Methods bound to the UI (setup, status, conflicts, settings, unlink); starts/stops the sync agent |
| `connect.go` | First-run connection: LAN discovery (`Discover`), address check with HTTP warning and TLS fingerprint (`TestServer`), pairing (`PairWithCode`) |
| `config.go` | Settings in the OS config dir (`%AppData%\Null Drive\config.json`, `~/.config/Null Drive/config.json`) |
| `keychain.go` | Device token in the OS keychain (Windows Credential Manager; Secret Service on Linux) |
| `scheme_linux.go` | Registers `nulldrive://` for an AppImage or an unpacked copy (`~/.local/share/applications`); skipped for packages in `/usr` or `/opt`, and when another copy already handles the links |
| `watcher.go` | fsnotify watcher, debounced, triggers a sync |
| `tray.go` | System tray (Windows/Linux); `tray_darwin.go` stub |
| `platform.go` | Open folder/logs, reveal file, start on login |
| `frontend/` | Svelte UI, reusing `../ui/src/lib`; `src/bridge.ts` is the only Wails-aware file |
| `build/appicon.png`, `build/windows/icon.ico`, `trayicons/` | Generated by `make icons` (`scripts/gen-icons.py`): don't edit by hand |
| `build/windows/winres.json` | Windows resources: icon, manifest (per-monitor DPI, long paths, as invoker), version info |
| `build/windows/installer/` | NSIS installer script and artwork (registers nulldrive:// per user) |
| `build/windows/msix/` | Microsoft Store package: `AppxManifest.xml` (protocol, startup task) and `Assets/` (generated by `make icons`); built by `scripts/build-msix.sh`, see `docs/STORE.md` |
| `internal/winetest/` | Windows stand-ins for `scripts/wine-test.sh` (`make wine-test`): a fake running copy, a command-line recorder, a ShellExecute launcher |
| `build/linux/` | `nulldrive-desktop.desktop` (menu entry, x-scheme-handler/nulldrive) and hicolor icons, generated from `build/appicon.png`; packaged by `scripts/build-linux-desktop.sh` |

The sync engine itself is `../shared/sync` (tested there and in `../server/internal/synctest`).

## Develop

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@v2.10.2
cd client
go mod tidy                 # first time: fetch Wails etc., write go.sum
wails dev                   # hot reload; or `npm run dev` in frontend/ for a browser preview with a demo backend
wails build                 # → build/bin/NullDrive(.exe)
```

Windows needs the WebView2 runtime (preinstalled on Windows 10/11). Linux needs `libgtk-3-dev` and `libwebkit2gtk-4.1-dev` to build, with the `webkit2_41` build tag (`go test -tags webkit2_41 ./...`; `wails build -tags webkit2_41`).

In the browser preview, sign in with any username and the password `demo-password`, or pair with the code `NULL-7K2Q-9F`. The demo "discovers" two servers; enter `https://nas.lan` to see the certificate-trust screen, or `drive.example.com` for the plain-HTTP warning.

While syncing, the app keeps a WebSocket to the server (`shared/client.Notifier`): the status card shows **Live** when pushes arrive within seconds, or **Polling** when the socket can't be held and it falls back to checking every 30 s.

## Linux packages

```bash
make linux-desktop          # = scripts/build-linux-desktop.sh <version> dist
```

Builds for this machine's architecture into `dist/`: `NullDrive-<v>-<arch>.AppImage`, `nulldrive-desktop-<v>-1.<arch>.rpm`, `nulldrive-desktop_<v>_<arch>.deb` and `nulldrive-desktop_<v>_linux_<arch>.tar.gz` (with a per-user `install.sh`). It's a `go build -tags desktop,production,webkit2_41` linked against the system's WebKitGTK; nfpm makes the `.deb` and `.rpm` and appimagetool the AppImage (both downloaded from their GitHub releases if they're not on PATH). The release builds it on an x86_64 and an arm64 runner.

`scripts/e2e-linux-desktop.sh APP SERVER` is the end-to-end test CI runs on every push: a real server, gnome-keyring as the Secret Service, the app under Xvfb; a file must download, a local file must upload, and an AppImage must register `nulldrive://`.

## Windows build and installer

```bash
make windows                # = scripts/build-windows.sh [version]
```

Builds, from Linux, macOS or Windows, into `dist/`:

| File | What |
|---|---|
| `NullDrive-<v>-Setup.exe` | Installer: per-user into `%LOCALAPPDATA%\Programs\Null Drive`, no admin prompt, Start menu entry, Apps & features entry, upgrades in place |
| `NullDrive-<v>-portable.zip` | The same `NullDrive.exe`, portable |
| `winget/*.yaml` | winget manifests for this version (submitting: below) |

It needs Go, Node 22, `makensis` (`apt install nsis`, `brew install makensis`, `choco install nsis`) and installs `go-winres` on first use. Wails' Windows target is pure Go, so this is a plain `go build -tags desktop,production` with the icon, manifest and version info compiled in; `wails build` on Windows produces the same program. CI builds the installer this way on every push (`windows-installer` job) and attaches it to releases.

Signing: set `WINDOWS_CERT_PFX` (path to a `.pfx`) and `WINDOWS_CERT_PASSWORD`, with `osslsigncode` installed, and both the exe and the installer are signed and timestamped. In GitHub Actions, add the repository secrets `WINDOWS_CERT_PFX_BASE64` and `WINDOWS_CERT_PASSWORD`.

What the installer does:

- Before replacing or removing files it runs `NullDrive.exe --quit`, which tells a running copy to stop syncing and exit (force-closing only if it hasn't after ~10 s).
- If the Microsoft Edge WebView2 runtime is missing (rare: it ships with Windows 11 and current Windows 10), it offers Microsoft's download page.
- The uninstaller removes the app, its shortcut, its autostart entry and its Apps & features entry. It asks before removing settings and the saved sign-in (`NullDrive.exe --forget`); a silent uninstall (`/S`) keeps them. The synced folder is never touched.

Tested here under Wine with a virtual display: GUI install, silent install, upgrade over an existing install, silent uninstall, the WebView2 prompt, `--quit` delivered to a stand-in running copy, `--forget`. The app's own window needs WebView2, which Wine can't run: the UI is covered by the frontend tests and the browser preview, and the CI `desktop` job builds and tests the client natively on Windows.

Submitting to winget (once per release, after the GitHub release exists): fork [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs), copy the three files from the release's `*.yaml` assets to `manifests/<first letter of owner>/<owner>/NullDrive/<version>/`, and open a pull request; or run `wingetcreate submit <folder>`. Microsoft's bots validate the installer (silent install and uninstall) before a human approves it. The Microsoft Store listing needs an MSIX package and a Partner Center account; that's the next step in Phase 8.
